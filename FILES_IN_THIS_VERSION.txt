THE WEEKLY PLAN (idea 90)

A "Week" button now sits in the bottom row: Week | Settings | Stop | Exit.
It opens a LANDSCAPE screen — the only one in the app — showing seven days
side by side.

  Mon 5:00 > 7:45h
    5:00 300m Work
   10:00  45m Lunch
   10:45 120m Yard Work
     —    Fitness          (parked, greyed, at the foot)

DRAGGING A BLOCK
  vertical    moves it within the day
  horizontal  changes its duration, 5 minutes a step, stopping at zero

  The axis you move in first locks the gesture, so there's no mode to
  remember. The header shows "↕ move  ↔ duration" so it's never a guess.

  Drag a duration to zero and the block PARKS — greyed, at the foot of the
  column, costing no hours and shifting no start times. Drag it back up and it
  returns. Nothing is deleted.

START TIMES ARE COMPUTED, never stored. A block's start is the day's start
plus everything above it, so moving a block moves every start time below it,
and the order IS the schedule.

TAP
  a block        duration exactly, move to another day, delete
  a day header   set the start time, pull in a layout, copy another day, clear
  +              add a block

THE WEEK MENU
  Pull in the default week     seven days from your weekday shapes
  Edit the default week        the same grid, seven weekday slots
  Delete this week             falls back to the default when it comes round

  In the default week: "Fill all days from current goals" puts your standard
  day in every column in one tap, then you thin out the weekend.

PAST DAYS lock and swap their header to "Mon 13:40 / 16:00" — actual over
planned, summed from the log.

APPLYING: on the first open of a new day, if that day has a plan, you're asked
"Apply today's plan?" with the goals listed. Prompted, never silent — it
overwrites goals you may have set deliberately.

NOT IN THIS BUILD
  Cross-column drag. Moving a block between days is in the block's popup for
  now; dragging out of one scrolling column into another is a bigger piece of
  work and can come later.

  Task tagging. Blocks already carry an empty task_ids field, so there's
  nothing to migrate when it arrives.
