FIXES THE CRASH WHEN RELEASING A DRAG ON THE WEEK SCREEN

Cause: on release, the screen redrew itself from INSIDE the touch handler. The
redraw removes every block — including the one still handling your finger.
Android answers that by sending the removed block a "cancel", which landed in
the same handler while it still thought a drag was in progress, so it redrew
again from inside the first redraw. That collision was the crash.

It was intermittent because it depended on whether Android still counted the
block as being touched at the exact moment it was removed.

Fixed by clearing the drag state first and deferring the redraw until the touch
event has finished.

A SECOND BUG IN THE SAME PLACE: release and cancel were handled identically, so
a cancelled drag would still save. Now a cancel saves nothing.

The main-screen sliders had that second bug too — a cancelled slide committed.
Fixed there as well. They never crashed, because they already cleared their
state before saving.
